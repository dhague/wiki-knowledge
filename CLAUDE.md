## Project: the wiki-knowledge plugin

This repo builds a **wiki-knowledge** Agent Skills package and Claude Code plugin (clean-room ingestion + retrieval over a git-backed markdown vault). Key resources, in order of authority:

- **`CONTEXT.md`** — domain glossary (page, kind, vault, typed edge, volatility, deployment mode, …). Read for vocabulary before writing anything that names a domain concept.
- **`docs/adr/`** — architectural decisions with rationale. Read before assuming *why* something is built the way it is. Load-bearing early ones: no MCP server (0001), no embeddings/agent-read retrieval (0002), stdlib FTS5 not embeddings (0006, strengthens rather than reopens 0002), plural kind-folders/singular kind-values (0008), frontmatter round-trip relaxed not byte-identical (0012), the bundled TypeScript layer (0017). The directory runs past 0025 — `ls docs/adr/` for the rest.
- **`wiki-plugin/skills/wiki-conventions/SKILL.md`** — authoritative on the frontmatter schema, folder structure, relative-markdown link rules, typed-edge vocabulary (`refines`/`contradicts`/`example-of`/`source`/`related`, one YAML key per relation holding a list of clickable links), and link encoding. `raw_source:` is the raw-artifact pointer (one markdown link, title = filename), distinct from the `source` edge key.
- **`docs/architecture.md`** — diagrams of the script layer and the skill→agent→cluster flow, as PNGs linked to interactive HTML under `docs/diagrams/`. A point-in-time snapshot: trust the code over the diagram if they disagree.
- **GitHub issues** — the wayfinder map [#1](https://github.com/dhague/wiki-knowledge/issues/1) tracks phases as child tickets, with *Decisions so far* / *Not yet specified* / *Out of scope* sections. It is updated far more often than this file.
- **`README.md`** — public-facing and derivative, not authoritative.
- **The enchiridion-vault** — ask it via `/wiki-ask` rather than reconstructing context by re-reading this file. It holds the narrative the other docs don't: why a decision went the way it did, what was tried and abandoned. It is ingestion output, not a spec — where it disagrees with `CONTEXT.md`, the ADRs, the conventions spec, or the tracker, those win. See the dogfooding-vault notes below.

If you're tempted to write a new standalone design doc, don't — extend one of the docs above instead, so there's never a second version of the truth.

### Standing conventions

- **Terminology: the wiki's units are "pages", not "notes."** Standardized in `CONTEXT.md`; "note" may still appear in old ticket prose.
- **Folder structure is kind-axed, with four plugin-fixed kind-folders**: `wiki/{concepts,entities,sources,synthesis}/` plus a user-extensible `raw/` inbox. Folders pluralize; kind *values* stay singular ([ADR-0008](docs/adr/0008-kind-folders-plural-kind-values-singular.md)). A pre-existing `wiki/<custom>/` is a peer placement target — opt-in, never auto-created, its value declared in `wiki/<kind>/KIND.md` ([ADR-0020](docs/adr/0020-custom-kind-folders.md)).
- **Raw filenames are preserved forever; link destinations are percent-encoded, not the filenames.** A file with external identity keeps its name verbatim; a plugin-created file carries a `YYYY-MM-DD-hhmm-` prefix bound at creation. Encoding lives at a single decode boundary in `enchiridion-ts/src/wikipage.ts` (charset: `%`, space, `()`, `#`, `<>`; unicode stays literal).
- **Model assignment**, not re-litigated per ticket: deterministic work is an `enchiridion` subcommand (no model), comprehension is Haiku, judgment (chunking, dedup, edge-typing, conflict resolution) is Sonnet. Start at the floor and escalate only on a measured failure. Expressed only in the Claude Code plugin's agent frontmatter; every other host runs the same procedures on its session model ([ADR-0026](docs/adr/0026-host-neutral-skill-package.md)).
- **The plugin lives at `wiki-plugin/`**; its `name` is `wiki-knowledge` in `.claude-plugin/plugin.json`, deliberately different from the directory name. Everything under `wiki-plugin/` is implementation — not a substitute for `CONTEXT.md`, `docs/adr/`, or the conventions spec. **`wiki-plugin/skills/` is the canonical hand-edited skill tree**; repo-root `skills/` is a generated copy of it that `npx skills add` installs from, refreshed only by `scripts/release.sh` ([ADR-0026](docs/adr/0026-host-neutral-skill-package.md)).
- **Git hygiene:** add paths explicitly, never `git add -A`. Resilio's `*.rsls` files and the `.claude/worktrees/` directory are both ignored (the latter by a per-clone `.git/info/exclude`, not `.gitignore`), so a clean `git status` does not mean they are absent. `temp/` is gitignored scratch space, so `git add temp/...` is a silent no-op.
- **Every change goes through a branch and a pull request**, solo repo or not — `main` is protected and rejects direct pushes (confirmed when the `v0.8.0` version bump had to go through [PR #197](https://github.com/dhague/wiki-knowledge/pull/197); [#198](https://github.com/dhague/wiki-knowledge/pull/198) records it). Create a worktree per task, push the branch, open a PR, and wait for the user to confirm the merge before cleaning up.
- **Release process:** cut releases with `scripts/release.sh <new-version>` on a PR branch. **Never tag or run `gh release create` by hand** — `tag-release.yml` does both, and builds the per-skill Joule ZIPs, once the version bump lands on `main`. There is no npm package. See `docs/agents/cut-release.md`.

### Script layer

**The script layer** (`enchiridion-ts/`) bundles to `dist/cli.cjs` + `node-sqlite3-wasm.wasm` via esbuild ([ADR-0017](docs/adr/0017-bundled-typescript-on-installed-interpreter.md)), run on an already-installed interpreter — Node (Claude Code, Joule Desktop) or Bun (OpenCode). **`wiki-plugin/bin/enchiridion` is a thin POSIX-sh shim** (#254) that execs `node` against the bundle; `ENCHIRIDION_BIN` overrides it for local dev. One subcommand per capability — `enchiridion --help` is the list; the notable spellings are below.

`wiki-plugin/scripts/` holds the **shipped host bundle** (`cli.cjs` + `.wasm` sidecar, committed per [#286](https://github.com/dhague/wiki-knowledge/issues/286)/[#290](https://github.com/dhague/wiki-knowledge/issues/290), resolved by the shim on plugin install). Every skill bundles a byte-identical copy at `wiki-plugin/skills/<slug>/scripts/enchiridion.cjs` — every skill, not a list of callers, because a portable skill resolves its script from its own base directory and no host-specific path may appear in skill text; identical content, so git stores one blob ([ADR-0026](docs/adr/0026-host-neutral-skill-package.md)). The per-host installers that used to live here (the OpenCode trio, the DSH bundle generator) are deleted.

**How `vault`, `page`, and `place` are spelled** (deliberate, not incidental): `vault` (bare or `vault root`) prints the resolved root, `vault move <old_ref> <new_ref>` moves a page and fixes every link inbound and outbound, and `vault kinds` lists every placement kind as JSON. `page get|set|merge <file> <key> …` is the frontmatter trio (`page`, not `frontmatter` — `page` is the domain noun in `CONTEXT.md`). `place <kind> "<title>"` computes a new page's vault-relative path. `place` **resolves no vault root** and `page` resolves none for a plain value, but an edge key's value may be a vault-relative ref, composed against the vault the file sits in — the file's own location wins and `$WIKI_ROOT` is not consulted (#548); `vault` does resolve the root, which is why moving a page lives there — it needs every other page's text to rewrite inbound links.

**The hooks are subcommands too** — `hooks.json` calls `bin/enchiridion hook session-start` / `hook post-tool-use` (`enchiridion-ts/src/hooks.ts`, dispatched by `cli.ts`), each reading its payload on stdin. Hooks run unattended, so they **fail open**: the subcommand swallows every handler error and exits 0, and `hooks.json` appends `|| exit 0`, so an error degrades one session's side effect instead of blocking session start.

**Three consequences worth knowing before editing.** First, **the `Vault` has no search-index facade** — `searchindex` imports neither `vault` nor the reverse: it reads `vaultgit` and computes `Status()`'s on-disk-versus-indexed comparison itself, walking `wiki/**.md` and diffing those refs against the index's ([ADR-0015](docs/adr/0015-search-index-view-of-committed-history.md)). Second, **`ingest` prints the post-commit tool-call cost summary** from a hook-written log, silent when no log exists — the SHA stays the first line of stdout either way. Third, **nothing self-heals the #114 kind-folder migration**: the script is deleted, and what survives is the check — `Vault.legacyKindFolders` detects an unmigrated vault and `ingest` refuses outright, spelling out the `git mv`, because `place.path` resolves canonical kinds from `KindFolders` and would otherwise split one kind across `wiki/concept/` and `wiki/concepts/`.

**Text search** is SQLite FTS5 via `node-sqlite3-wasm` ([ADR-0006](docs/adr/0006-stdlib-fts5-not-embeddings.md)). Key gotcha: **the index is a materialised view of `HEAD`, not the working tree** ([ADR-0015](docs/adr/0015-search-index-view-of-committed-history.md)) — an uncommitted page is structurally invisible to search. `.wiki-knowledge/index.db` is gitignored and never uses WAL (Resilio + SQLite WAL sidecars corrupt). Query tokenization phrase-quotes by default; `--raw` is the escape hatch for bare FTS5 `MATCH`.

**One contract a future edit must not break** (property-tested in `wikipage.test.ts` via `fast-check`): a page **move changes nothing outside a link, and all links still resolve** — including frontmatter markdown links (typed edges, `supersedes`, `raw_source`), spliced by the same whole-document rule as body links. Two independent oracles guard it: the raw-text scan (`iterLinks`) and frontmatter edges read through the YAML parser (`newPageRecord`), so a link the scan goes blind to cannot make both sides agree (#489). Byte-level, not line-level, because a flattened fold means a correct move can cost a line. Frontmatter round-trip is likewise not byte-identical, though key *order* is preserved: the divergence is scalar quote style plus long scalars folded past the line width on pages written before [ADR-0024](docs/adr/0024-emitted-lines-are-not-folded.md) ([ADR-0012](docs/adr/0012-frontmatter-round-trip-relaxed.md)).

**Dev setup:** `enchiridion-ts/package.json` holds the scripts and the `engines.node` floor; CI (`ts-enchiridion.yml`) runs the matrix on Node.js LTS and Bun, and both must pass. `npm run build` emits the bundle + `.wasm` sidecar, `npm test` is Node's built-in runner via `tsx`, and `test:bun` needs `bun` on PATH. Two things the files don't advertise: `wiki-plugin/tests/bin_enchiridion.bats` covers the shim (`brew install bats-core`; run it from the repo root), and the skill tree's structural checks live in `enchiridion-ts/src/skills.test.ts` — frontmatter `name` matches the directory, descriptions are non-empty, no host-specific spelling in portable prose, and `cut-release` carries a real `metadata.internal: true` — so `npm test` covers the package contract too.

### Current state

- **Ingestion, retrieval, and auto-ingest are all built**, not just specced. [#11](https://github.com/dhague/wiki-knowledge/issues/11) is the closed roll-up spec for `wiki-ingest` (Sonnet) and `wiki-researcher` (Haiku).
  - **Ingestion:** `wiki-ingest` authors an `IngestPlan` JSON document, executed atomically by `enchiridion ingest`. The plan is resolved once so validate and execute can't diverge (#125), there is no rollback, and writes are idempotent so rerun-after-fix is safe. Three actions: `ingest`, `synthesize` (the confirmed synthesis-page save), and `consolidate` (one survivor absorbs the pages it names — a lossless delete, not a supersede, [ADR-0021](docs/adr/0021-consolidation-is-lossless-delete-not-supersede.md)). The schema's only spec is `ingest.ts`'s module comment.
  - **Auto-ingest** ([#37](https://github.com/dhague/wiki-knowledge/issues/37), closed): `/wiki-watch` — a user-run foreground watcher, not a daemon or hook — Ctrl-C to stop.
  - **Retrieval:** `wiki-researcher` (Haiku) + the `wiki-ask` skill, which hold the pipeline and its ~2-hop, ~12-page budget. Two invariants worth carrying here: recency is never a re-ranking signal except for explicitly time-anchored questions (and even then a `supersedes` edge wins), and **a subagent cannot ask for the confirmation that gates a write** — so `wiki-researcher` *proposes* a `save-candidate` block and the invoking session saves on explicit yes (`Write` is removed from its tools).
- **Remaining per the wayfinder map ([#1](https://github.com/dhague/wiki-knowledge/issues/1)):** the OpenCode port ([#90](https://github.com/dhague/wiki-knowledge/issues/90)–[#94](https://github.com/dhague/wiki-knowledge/issues/94)) is closed, and its install mechanism — with the DSH bundle generator — was retired in favour of one host-neutral skill package ([#545](https://github.com/dhague/wiki-knowledge/issues/545), [ADR-0026](docs/adr/0026-host-neutral-skill-package.md)). Statusline and evals ([#47](https://github.com/dhague/wiki-knowledge/issues/47)) remain, and `wiki-doctor` ([#74](https://github.com/dhague/wiki-knowledge/issues/74)–[#79](https://github.com/dhague/wiki-knowledge/issues/79)) is still at the design-question stage, not scoped into build tickets.
- **`enchiridion save-session` is Claude-Code-only in practice.** The code still carries an OpenCode adapter — `$OPENCODE_SESSION_ID`, tie-broken on tracker state, transcript fetched via `opencode export` (whose stdout goes to a temp *file* because it truncates on a pipe) — but that variable was injected by the `session-tracker` plugin #545 deleted, so no current install path sets it; a host-neutral session-id source is follow-up work. Fetch is the only host-specific step; everything downstream, including the `**Source:**` label, is one seam in `transcriptcapture.ts`.
- **`/to-spec` on this repo is wayfinder-mapped**, not one-feature-per-invocation — phases are charted as child tickets off [#1](https://github.com/dhague/wiki-knowledge/issues/1), so name the phase(s) in the invocation; the skill itself does not interview you.
- **Eval strategy:** the hand-authored "golden vault" is shelved for a small synthetic fixture — the irreducible deliverable is the **property list**, not the pages. The intended shape (~8 fake pages at `wiki-plugin/evals/fixtures/` plus `evals/PROPERTIES.md`, human-owned and agent-drafted per [ADR-0005](docs/adr/0005-tdd-for-scripts-evals-for-agents.md)) **does not exist yet** — `wiki-plugin/evals/` holds only the `measurement/` tool-call harness. Tracked at [#47](https://github.com/dhague/wiki-knowledge/issues/47), with the concept-fragmentation property at [#457](https://github.com/dhague/wiki-knowledge/issues/457); the harness itself (headless `claude -p`, pass-rate, an LLM judge) is still fog.
- **Plugin version: `0.17.0`** (`wiki-plugin/.claude-plugin/plugin.json`) — don't assume `main` matches any given tag.

### The dogfooding vault

- **Live vault at `$WIKI_ROOT`** — a separate git repo (own `wiki/`, `raw/`, history), not part of this one, running `wiki-knowledge` in query-from-anywhere mode via a local-directory marketplace in its own `.claude/settings.json`. This is real usage: treat anything found working in it as a genuine bug report, not a hand-run to reproduce and discard.
- **Always invoke scripts as `WIKI_ROOT=<vault root> <path to script>` when touching vault files.** `$WIKI_ROOT` is the highest-priority rule in the vault-root resolution order ([ADR-0004](docs/adr/0004-deployment-modes-and-vault-root-resolution.md)); everything else guesses from `cwd`, and that guess is actively wrong from this repo — there is no `wiki/` or `.wiki-root` marker here, so resolution falls through to "`cwd` is the vault root" and a script writes pages into the source tree. Set it per-invocation, not exported.
- **This vault is long-term memory** — look things up via `wiki-ask` rather than reconstructing context by re-reading this file and grepping the tracker.
- **`/save-conversation`** finds its session's transcript via a `SessionStart` hook (`hooks.json` + `enchiridion hook session-start`, recording `transcript_path` per `session_id` under `.claude/wiki-knowledge/sessions/<session_id>.json`) and names the raw file from an **agent-authored slug** — a phrase naming what the session covered, not how it opened. Filename: `raw/conversations/<YYYY-MM-DD-hhmm>-[<slug>-]<short-id>.md`, sanitized (`[^a-z0-9]+`→`-`); the slug drops out when it sanitizes to nothing, and `short-id` is the first UUID segment (the OpenCode `ses_…` spelling survives in the code but no current install path reaches it — see *Current state*). The name binds once: a re-save rewrites that file in place, so a topic change should start a new session.
