# Skills are host-neutral; model tiers, hooks and subagents stay in the Claude Code plugin

The plugin's eight skills are authored once, host-neutrally, and published as one Agent Skills package: canonical in `wiki-plugin/skills/`, copied verbatim to repo-root `skills/` at release, installed anywhere with `npx skills add dhague/wiki-knowledge --all`. Everything that cannot be expressed portably — the `model: sonnet|haiku` tier split on the three subagents, `hooks/hooks.json`, the `bin/enchiridion` shim and the marketplace install — stays in the Claude Code plugin, the only host surface that can carry it. The per-host installers are deleted rather than maintained alongside: the OpenCode npm deployer with its `session-tracker` and `wiki()` plugins, and the generated DSH profile bundle. The hosts read the same `.agents/skills/` directory natively — the `skills` CLI installs OpenCode skills there, and DSH scans `<projectRoot>/.agents/skills` at rank 200 and `~/.agents/skills` at rank 500 — so one install command covers both.

## Why

Four install surfaces were carrying four different subsets of the same eight skills: the Claude Code marketplace (8), the OpenCode npm deployer (6 — it dropped exactly `wiki-lint` and `wiki-export`), the generated DSH bundle (8 skills read in place, plus three agent-as-tool rows), and per-skill ZIPs for Joule (2). Each was hand-maintained, and the same skill text was being read by DSH and OpenCode from `wiki-plugin/skills/` with Claude-Code-only prose intact — the `~/.claude/plugins/cache/...` binary glob and the `wiki(args=[...])` branches. Moving to the standard removes three mechanisms, and the skills' own text becomes the one thing that must stay portable because it is now what every host reads.

## Considered options

- **Keep the per-host generators.** Highest per-host fidelity — OpenCode kept model-pinned agent copies and its `wiki()` tool, DSH kept `deepseek-flash` routing. Rejected: three mechanisms, three subsets, three places for the same skill text to drift, and the portable text has to be portable anyway for the package to exist.
- **Adopt the sibling `plugins` CLI and the `.plugin/` open-plugin format.** It reads `.claude-plugin/` manifests, so it would have cost zero new files, and it reaches Cursor, Codex, Grok Build, Kimi Code, Copilot CLI and VS Code. Rejected: its `TARGET_DEFS` has no OpenCode, no Gemini CLI, no DSH and no extension point (an unknown `--target` exits 1); it copies content byte-for-byte with no model handling at all; hooks are the Claude Code convention with `${*_PLUGIN_ROOT}` rewritten and silently ignored elsewhere; it has no `update`, no `remove`, no lockfile and no ref pinning; the upstream repo 404s and the published tarball carries no licence. It remains available as a documented side door, because it does work from the manifest we already ship.
- **Canonical tree at repo root, plugin tree generated.** Same short install command, but the generated copy would then be the one Claude Code installs — a forgotten regeneration would ship stale skill text to the primary host. Rejected in favour of making the product tree the hand-edited one.
- **Rename `cut-release` so the installer cannot see it.** Breaks Claude Code, which discovers skills only as `<dir>/SKILL.md`, and a `@file` mention is not skill activation. `metadata: internal: true` in the frontmatter is the installer's own suppression mechanism and leaves every host's discovery untouched; it must be a real YAML boolean, since the check is `metadata?.internal === true` and a quoted `"true"` is ignored silently.

## Consequences

- **Accepted losses.** OpenCode loses the `wiki()` tool (skills run the per-skill bundle directly), the model-pinned agent copies, and `session-tracker`'s session-id tie-break evidence — `save-session` falls back to environment detection plus the host's own transcript export. DSH loses the agent-as-tool rows and its `deepseek-flash` routing; its tool-call cost log was never ported ([#534](https://github.com/dhague/wiki-knowledge/issues/534)).
- **The tier split is the host's routing concern** wherever the host cannot express it — the position `generate-dsh-bundle.py` already took, generalised. Claude Code keeps the tiers because its agent frontmatter is the one surface that can carry them.
- **Each skill that calls the script layer ships its own copy** of the bundle (~2.6 MB) and resolves it relative to the skill's own base directory, which is the one form every host resolves (`agentskills.io/specification`). The runtime is resolved the same way: `node` where it exists, `bun` where it does not — OpenCode guarantees only Bun, and requiring Node there is what the retired in-process `wiki()` tool existed to avoid. Git is content-addressed, so the repository stores one blob however many skills bundle it; the cost is roughly 21 MB per published tree in a checkout and in the release tarball.
- **Two trees exist and must stay byte-identical.** The freshness job in `ts-enchiridion.yml` runs on every PR and fails if repo-root `skills/` diverges from `wiki-plugin/skills/`.
- **Nothing is published to npm.** `tag-release.yml` tags, creates the GitHub Release and builds the eight per-skill Joule ZIPs; it no longer sets up Python, assembles an OpenCode package or publishes.
