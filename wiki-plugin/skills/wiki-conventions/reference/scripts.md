# Script catalogue and runtime contract

The runtime rules for calling the script layer, and every `enchiridion` subcommand the skills call: what to call it for, and its usage. `enchiridion --help` is the complete list, including the few the procedures never reach.

## Script runtime contract

**The vault root — the one place this rule is stated; every other skill points here.** The script resolves it itself: `$WIKI_ROOT` when set and non-empty, else the nearest ancestor of the working directory carrying a `wiki/` or `.wiki-root` marker, else the working directory.

One exception: `page` resolves no root for a plain value — an edge value's vault-relative ref is composed against the vault the file sits in, so the file's own location wins and `$WIKI_ROOT` is not consulted.

**Batch independent invocations** — several `search` queries, say — into one shell call rather than issuing each separately; every extra tool call costs a full turn.

**`--json` output contract — one dialect, one spelling.** Two shapes, and the choice is *how many documents*, not the outer JSON type:

- **JSON Lines** — one compact object per line, nothing at all when there are no rows (never `[]`). Row-producing commands: `search`, `superseded-by`, `ingest-scan`, `check`, and `discover`'s single-page mode. Consume by splitting stdout on newlines; never buffer the whole result first.
- **One document** — a single compact JSON value on one line, the value itself an array where the run is a table (`read-page`, `read-pages`, `discover --plan`, `vault kinds`, `export --candidates`, `search --status`/`--reindex`). Consume with one `JSON.parse(stdout)`.

Never indented, never pretty-printed. **Failure is the other half of the contract**: message on stderr, non-zero exit, same whichever host ran it. **One exception — `page set --json` means *input*, not output**: it parses the value argument as JSON, and is the one subcommand whose stdout no consumer parses.

## Subcommand catalogue

| Subcommand | Call it for | Usage |
|---|---|---|
| `enchiridion discover` | Discovery before ingesting — BM25 overlap classification for every page a draft plan proposes, plus vault's tag vocabulary. Call during ingestion step 3, before writing real `IngestPlan`. Emits only actionable hints (`duplicate`/`refines`/`related`); `distinct` hits (score below `relatedThreshold`) are filtered before output — their absence means "safe to mint." Recall is unbounded by default; `--limit` is an optional safety cap (default 0 = unbounded). | `enchiridion discover --plan <draft-plan.json> [--limit N] [--duplicate-threshold F] [--related-threshold F]` → `{"pages": [{"title", "candidates": [{page_ref, title, score, hint, summary, tags, volatility, superseded_by}]}], "vocabulary": [{"tag", "count"}]}`. Single-page mode (`--title`/`--summary`/`--body-file`) for ad-hoc checks, JSON Lines. `--tags-containing "a,b,c"` (case-insensitive substring OR match) and/or `--tag-count "x,y"` (exact match, 0 if the tag doesn't exist yet) each swap the `vocabulary` array for a named field in the same document — `tag_matches` (`["tag1","tag2"]`) for the former, `tag_counts` (`[{"tag","count"}]`) for the latter — so `--plan` output is exactly one JSON document whatever flags you pass. Pass both, derived from the draft's own candidate tags, instead of the full vocabulary dump. |
| `enchiridion search` | Any vault search. | `enchiridion search "<terms>" [--tag T] [--tag-any T] [--kind K] [--since DATE] [--until DATE] [--date-field FIELD] [--volatility V] [--limit N] [--include-superseded] [--raw] [--json]`. Also `--reindex [--full]` and `--status`. |
| `enchiridion read-page` | Reading a page's full content by vault-relative ref — frontmatter + body. The read-only companion to `search`; a host that cannot read files directly uses this in place of one. | `enchiridion read-page <page_ref>` prints the page's raw markdown; `--json` emits `{page_ref, frontmatter, body}` as one compact line. |
| `enchiridion superseded-by` | Filtering retrieval candidate set for currency — resolving each candidate to its current page. Call during retrieval step 4, once frontier is expanded. | `enchiridion superseded-by <page_ref> [<page_ref> ...] [--json]` → `--json` is JSON Lines, one `{seed, active, chain}` per candidate per line; `active == seed` means current. |
| `enchiridion ingest` | Executing an `IngestPlan` — resolve, validate, write, commit — after agent assembles plan. | `enchiridion ingest --plan <path>`; add `--dry-run` to validate and print without writing. A writing run prints the commit SHA on the first stdout line, then the written page refs (`<op> <ref>` per line, plan order), then the tool-call cost summary when a hook log exists (silent otherwise) — the order `ingest --help` declares. `enchiridion ingest --ignore <raw_rel> [--ignore <raw_rel> …] [--ignore-comment <text>]` appends to folder's `.ingestignore`; `--ignore` is repeatable so multiple paths can be bulk-added in one call. |
| `enchiridion ingest-scan` | Sweeping `raw/` for files needing ingestion (never-ingested, changed-since-ingestion). | `enchiridion ingest-scan [folder] --json` → JSON Lines, one scan row per line. |
| `enchiridion check` | Running the vault's mechanical checks — the `wiki-lint` procedure's engine, and the post-ingest lint pass. | `enchiridion check <slug> --json` → JSON Lines, one finding per line, nothing when clean. `enchiridion check --all [--json]` runs every mechanical check in one call — the form both the `wiki-lint` and `wiki-ingest` procedures report on; each row then gains its `check` slug, and the text form prefixes each line with it. Omitting both the slug and `--all` is an error, not a silent no-op. `--min-similarity <0-1>` sets the `concept-fragmentation` cutoff; `check --help` names every slug. |
| `enchiridion assess` | Reading one candidate cluster's members in full before recommending a Consolidation — the `wiki-lint` procedure's assessment step. Reads the same committed `HEAD` the check scored, so the bodies judged are the ones the cluster was found in. | `enchiridion assess <page_ref> [<page_ref> ...]` → one JSON document: `{head, members: [{page_ref, blob_oid, fingerprint, title, bytes, text}]}`. Exits non-zero naming the page when a member is not a readable committed page; the cluster could not be assessed. |
| `enchiridion read-pages` | Reading page **bodies** in bounded batches for the `wiki-lint` procedure's judgment checks, including its implicit-concepts sweep. Unlike `read-page` it reads committed `HEAD`, so an uncommitted draft is invisible; it returns bodies without frontmatter, caches what the run already read, and bounds a sweep's reads. | `enchiridion read-pages <page_ref> [<page_ref> ...]` reads exactly those pages — any page at `HEAD`, flagged or not, and never truncated by a batch cap. With no refs it sweeps the eligible pages (`wiki/<kind-folder>/<file>.md` at `HEAD`, minus any `--exclude <ref>`, repeatable) in batches of `--limit` (default 12) or `--max-bytes` (default 49152), continuing from `--after <ref>`. `--budget <n>` (default 60) caps the bodies one lint run's sweep newly reads, and `--reset` opens a run by dropping the ledger before the read. One JSON document: `{head, eligible, returned, cached, next_after, remaining, budget: {spent, cap, exhausted}, pages: [{page_ref, blob_oid, title, bytes, cached, body}]}`. Exits non-zero naming a ref that is not a page at `HEAD`. |
| `enchiridion exclusion add` | Recording a declined Consolidation cluster so lint stops proposing that exact member set. Captures the members' `HEAD` revisions and commits the kind-folder's `CONSOLIDATION_EXCLUSIONS.yaml` on its own. Add records with this command, never by hand — deleting one by hand is how a cluster is un-declined. | `enchiridion exclusion add <page_ref> <page_ref> [<page_ref> ...] --reason "<why>"`. Every member must sit in one consolidatable kind-folder; at least two are required. Prints the registry's vault-relative ref. Refuses when `HEAD` moves mid-capture, or when the registry is malformed. |
| `enchiridion fix` | Applying one mechanical fix by slug. | `enchiridion fix <slug>` prints the page refs it rewrote. Fix slugs need not match check slugs. `enchiridion fix consolidation-exclusions [--prune]`: without `--prune` it canonicalises the registries, refreshes a cached blob ID whose fingerprint still matches, and collapses identical records; `--prune` additionally drops members that no longer match `HEAD` and deletes a record left with fewer than two — confirm first, because it discards a decline a human made. |
| `enchiridion export` | Rendering the vault as a static HTML site — the `wiki-export` procedure's engine. | `enchiridion export [--single-file] [--out <path>] [--raw] [--force] [--allow-dirty] [--title <title>]` with either `--starters <ref[=annotation]>...` or `--start-page <ref>`. `--out` defaults to `web/`, or `wiki.html` at the vault root under `--single-file`; `--raw` includes the `raw/` section. Also `--candidates`, and `--save-title`/`--save-start-page` which write `.wiki-knowledge/config.json` and export nothing. |
| `enchiridion watch` | Long-running filesystem watcher over `raw/` with per-file debounce, exclusive lock, queue file — launched by the `wiki-watch` skill. | `enchiridion watch [--vault ROOT] [--debounce SECONDS] [--poll-interval SECONDS]`. `enchiridion watch [--vault ROOT] --dequeue <raw_rel>` removes one queue entry. |
| `enchiridion vault` | Resolving vault root, listing all available kinds, or moving a page (rewrites all inbound links across vault and outbound links inside moved page). | Bare `enchiridion vault` (or `enchiridion vault root`) prints resolved root. `enchiridion vault kinds` lists every kind as one compact JSON array — the four canonical kinds (`canonical: true`) plus any custom kind-folder; each entry: `{kind, folder, canonical, consolidatable, definition}` — `consolidatable` says whether `concept-fragmentation` scores the kind (`true` for `concept`, never for `entity`/`source`, otherwise the `KIND.md` declaration), and `definition` is the `KIND.md` `{kind, summary}` or `null`. `enchiridion vault move <old-page-ref> <new-page-ref>` prints each changed page ref, one per line. |
| `enchiridion init` | Scaffolding new empty vault: folders, `.gitignore`, git init, optional `settings.json`. | `enchiridion init <path> --mode {query-from-anywhere|dedicated} [--plugin-root DIR]`. |
| `enchiridion save-session` | Capturing current session's transcript as raw file in vault. Called by the `save-conversation` skill. | `enchiridion save-session [--slug "<phrase>"]`. |
| `enchiridion page` | Frontmatter edits during ingestion. Takes a **file path**; a non-edge value is written verbatim, an edge value is composed against the vault the file sits in. | `enchiridion page get <file> <key>` (exits non-zero when key absent) · `page set <file> <key> <value> [--json]` · `page merge <file> <key> <json-list>`. For an edge key — `raw_source`, `supersedes`, `refines`, `contradicts`, `example-of`, `source`, `related` — every value is either exactly one markdown link, kept exactly as written (its destination is not inspected, so a URL or anchor link passes), or a **vault-relative page ref** like `wiki/concepts/foo.md`, which is composed to a `[Title](../dest.md)` link exactly as `ingest` composes plan `edges`; never hand-build the link. Anything that is neither — prose, a bare URL, an absolute path, a `..`-escaping path — fails, naming key and value, as does a ref that names no file. `page set` **replaces** a list-valued key — one value becomes a one-element list — while `page merge` **unions** into it. `tags` is the one list-valued key that is not an edge: a bare value becomes a one-element list, and more than one is a JSON array — `page set <file> tags '["a","b"]'`, with or without `--json`, since that is the shape `page merge` already takes. A value that is neither a JSON array nor a plain string is refused, because a scalar there indexes as no tags at all. `raw_source` holds a single link, so set it with `page set`; `page merge raw_source` fails. |
| `enchiridion place` | Computing new page's vault-relative path from kind and title — the exact ref `ingest` will write, so the one a plan's edge must name for a page it creates. Resolves the vault root, so any discovered custom kind-folder is a valid kind alongside the canonical four. | `enchiridion place <kind> "<title>"`. |
| `enchiridion commit` | Writing one structured git commit per ingestion/edit manifest: stages paths, gates on chain-of-evidence, returns SHA. Only for a hand-built manifest — `enchiridion ingest` commits its own plan. | `enchiridion commit --manifest <path>`. |
